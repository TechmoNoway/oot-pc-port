# Native port architecture

## Current implementation

The executable is a Windows host written in C17. It queries the system, allocates and releases memory using Win32, and checks those operations with a self-test. The standard build maps verified image packages as data. A separate private [startup-bootstrap build](startup-bootstrap.md) includes selected original code and can execute an explicitly requested experimental loader prefix with trace diagnostics. It does not complete startup or provide gameplay.

The offline Python [input inspector](input-inspection.md) reads NUP, NSO, NPDM, and extracted ExeFS metadata. It verifies the NUP catalog and selected ExeFS file hashes without extracting the game tree.

[Segment preparation](segment-preparation.md) decodes NSO LZ4 blocks or ZBIC frames and checks hashes over the decoded bytes. It writes plain NSO files and a manifest under `build/`. LZ4 decoding is implemented in the project; the ZBIC helper links a pinned external dependency stored under `toolchain/`.

The [offline linker](offline-linking.md) reads MOD0, dynamic tables, and symbols, establishes guest addresses for private module images, zero-initializes BSS, and applies supported AArch64 relocations. Images can be exported only after a complete link. A [native image bridge](runtime-images.md) now packages exact linked segment and BSS ranges and maps them into caller-owned native backing through checked guest addresses, with a guarded synthetic stack. This does not execute guest code or establish process startup.

[ARM64 analysis](arm64-analysis.md) uses a separate disassembly backend and project control-flow logic to survey prepared code. It reports evidence-based entry candidates and follows direct edges; indirect targets and nonlocal-return semantics remain explicit gaps. Optional semantic coverage classifies exact encodings using the lifter's decoder without executing game code.

The [ARM64 lifter](arm64-lifter.md) emits C17 for a bounded raw code range. It maintains explicit X registers, SP, PC, and NZCV, returns to a dispatcher when PC leaves the translated range, and enforces an instruction budget. Scalar and paired transfers use [checked guest memory](guest-memory.md) with read/write permissions and whole-access preflight. Generated synthetic programs compile to native Windows code and are compared with Unicorn ARM64 for state, memory, and selected access faults. A synthetic translated stack frame also runs on stack backing supplied by the native image bridge. The separate startup experiment now connects this emitter to original loader code, a minimal process context and explicit service stops; general game execution remains incomplete.

[Leaf verification](leaf-verification.md) adds a conservative structural boundary for short, acyclic register-only regions with standard returns and preserved X18-X30/SP. Eighteen complete synthetic functions cover arithmetic mixing, signed minimum, bitfield insertion, signed remainder, carry propagation, branching, conditional comparisons, widening/full multiplication, bit normalization, rotate round trips and CRC chains. Native results are checked against independent formulas as well as ARM64 execution. Metadata-rooted game candidates are surveyed statically and remain unexecuted.

The [controlled leaf dispatcher](leaf-dispatch.md) copies and validates generated entry/CFG metadata, binds entries to trusted compiled C symbols, and checks entry, return, stack alignment/bounds, NZCV, and paused state. It executes one lifted instruction at a time on a private state copy and commits only after the step satisfies its CFG, retirement, and register contract. Synthetic native caller/callee chains match ARM64 reference execution, and a synthetic mapped image can supply its stack. Game callbacks remain unregistered and unexecuted through this leaf profile.

## Planned boundaries

1. Input inspection: identify the game build, inspect module metadata, and validate user-provided inputs.
2. Segment preparation: decode and verify NSO segments while preserving memory offsets and BSS metadata.
3. Module loading: establish the guest memory layout, apply relocations, and resolve module references without executing guest code.
4. Offline translation: translate supported ARM64 instructions to C while recording unsupported instructions and unresolved control flow.
5. Host services: provide the threading, synchronization, files, saves, input, audio, and timing behavior the game uses, then run translated module initialization.
6. Graphics: establish the graphics API boundary, translate required shaders, and connect it to a native renderer.

Each boundary needs a verifiable milestone before work advances to gameplay. A successful compilation is not evidence of correct game execution.

The [hash-bound registry](bound-dispatch.md) now pins compiled symbols to the initial runtime snapshot and exact current text ranges. A separate verified linear FP/LR caller supports direct calls to register-only leaves, stages its stack save before commit, and preserves state/stack ownership across yields. Only synthetic functions have been registered and executed through this registry.

A separate [local-stack dispatcher](stack-dispatch.md) supports fixed 16-256-byte frames, checked local scalar/pair memory effects, and direct framed-to-framed calls in bounded acyclic graphs. It uses explicit activations, one instruction budget, staged store commits, and checks all owned ancestor/current frame bytes and active code on resume. Synthetic three-level calls, individual instruction prefixes, and a full 16-frame stack boundary match independent reference execution.

A separate [framed CFG policy](stack-cfg.md) now adds acyclic conditional control flow and explicit scalar/pair X19-X28 saves with matching restores. The dispatcher validates CFG edges, per-phase writable masks, save-slot isolation, and weighted longest paths through nested calls. Schema 3 selects this policy; earlier profiles retain their rules.

A separate [fixed-layout policy](stack-layouts.md) now supports SUB/ADD allocation, offset FP/LR records, sparse save slots, delayed FP setup, and normalized negative FP-relative accesses. Per-instruction SP/FP/LR/ownership metadata protects allocated frames until actual deallocation, including yields after restoring the frame record. Mixed-layout nested calls and a 16-frame/full-stack boundary match the reference. Schema 4 opts into this policy.

The [static profile survey](function-profile-survey.md) evaluates unchanged metadata-rooted game regions with actual production verifiers and real dependency closures, without generating C or executing candidates. The current default local 1.1.1 results accept 40,188 leaf candidates and no framed candidates under the older policies. Diagnostic observations do not bypass semantics or establish original function identity.

A separate [pointer authentication model](pointer-authentication.md) now provides QARMA5/VA39 instruction-key A/B signing, AUT, and RETAA/RETAB semantics through an explicit PAC context and separate callback ABI. Native synthetic tests compare actual signed bits, poisoned pointers, nested frames, budgets, and faults against a PAuth-enabled reference. Canonical signing is a required precondition; the older profiles and surveys keep their original policies.

A separate [PAC-aware policy/dispatcher](pauth-stack-dispatch.md) integrates the model through policy 4/schema 5. It retains the image and immutable key context, validates signed-LR phase transitions, and protects approved returns and owned frames across yields. Synthetic nested calls and 16-frame/full-stack cases match the enabled reference on MSVC and GCC. Its separate static 1.1.1 survey accepts 1,686 PAC framed candidates without generating callbacks or running game code.

The raw lifter now supports [no-offset RCpc ordered loads](ordered-loads.md) on an aligned Normal-memory subset. All scalar/pair/acquire backend transfers share a lock per linked instance, with separate per-thread state/fault views and explicit shared-backing ownership. Synthetic values/faults match the reference, and real native threads exercise ordered publication and transfer atomicity. This chooses a stronger total order; it does not implement a guest scheduler or every Arm weak-memory outcome. Existing function profiles do not gain new memory permissions.

A separate [checked-read policy](checked-reads.md) now adds explicit read capabilities for retained image regions through policy 5/schema 6. It anchors read opcodes to original text, checks dynamic address bounds/permissions/frame ownership, captures one operand through the real memory backend, and validates the callback against a private read-only snapshot and independently computed full state. Saved slots and ancestor frames stay protected; external stores and unowned buffers remain unsupported. Synthetic ordinary/RCpc loads and nested PAC calls match the enabled reference on MSVC/GCC. Its static survey accepts 1,688 structural candidates, subject to runtime read obligations, while policy 4 remains at 1,686.

A separate [LR-pair frame policy](lr-pair-frames.md) adds policy 6/schema 7 for pre-index LR/callee-save allocation and matching post-index restoration with an unchanged FP. Exact original pair words are checked against bound text. Mixed LR/FP/leaf calls preserve per-activation SP/FP/LR, signed records, saved masks, ownership, and finite bounds. Synthetic prefix and full-depth comparisons pass on MSVC/GCC. The static accepted count remains 1,688; passing the new allocation shape exposes further callee and write-effect blockers.

The [callee audit](callee-audit.md) records exact dependency frontiers with distinct caller/target edges, separate root-reference counts, diagnostic direct-target probes, and relocation-backed PLT/GOT snapshot annotations. It reproduces policy-6 hashes and aggregate outcomes without extending discovery or registering callbacks. Of 5,463 missing frontier targets, 3,488 already have blocked metadata entries, 1,973 are PLT stubs, and two are unseeded text targets. It identified 72 PLT stubs resolving in the linked snapshot to already verified register-only leaves, motivating the explicit transfer boundary below. Snapshot resolution alone does not authorize an indirect call or establish a service ABI.

The separate [checked PLT policy](plt-dispatch.md) now supplies that boundary through policy 7/schema 8. It preserves each original stub instruction, gives LDR only its exact read-only GOT operand, validates complete state effects, pins one approved leaf target and its code hash, and protects caller frames across bridge/leaf yields. Synthetic mixed calls and full-depth cases match the enabled reference on MSVC/GCC. All 72 audited frontier stubs pass original-byte verification; a fresh static comparison accepts 1,703 policy-7 candidates while policy 6 stays at 1,688. Nonlocal returns, general indirect targets, service dispatch and broader memory effects remain separate work.

The [conditional-compare milestone](conditional-compare.md) adds exact CCMP/CCMN value forms to ordinary/PAC emission and the existing register/flag policies. Independent mathematical flag checks, complete artificial leaves, and actual schema-8 PAC/PLT call prefixes pass on MSVC/GCC without changing state/descriptor ABIs or memory permissions. Fresh discovery reaches 130,808 regions with PAC enabled and the global eligible bridge catalog reaches 404; policy-6/7 acceptance remains 1,688/1,703. No game callbacks are generated or executed.

The [widening-multiply milestone](long-multiply.md) implements signed/unsigned multiply-add/subtract with W multiplicands and X accumulation, including multiply/negate aliases. Unsigned C intermediates preserve the required modular result without signed overflow. Independent arithmetic, complete artificial leaves and actual schema-8 PAC/PLT prefixes with saved X19 destinations pass on MSVC/GCC. Fresh discovery reaches 133,760 PAC-enabled regions; ordinary leaf acceptance rises to 40,144 and policy-7 acceptance to 1,710, while policy 6 remains 1,688. The global eligible bridge catalog contains 423 entries. Profile permissions and ABI layouts are unchanged.

The [one-source integer milestone](bit-operations.md) implements RBIT/REV16/REV32/REV/CLZ/CLS with exact W/X variants, zero/all-ones boundary behavior and unsigned C helpers. Independent string/byte checks, complete leaves and actual PAC/PLT prefixes validate saved W19/X19 writes and full restoration on MSVC/GCC. Static discovery reaches 135,020 PAC-enabled regions; ordinary leaf acceptance rises to 40,175, while policy-6/7 acceptance remains 1,688/1,710. The eligible global bridge catalog reaches 430, without expanding any registry limit or runtime capability.

The [high-product milestone](high-multiply.md) implements UMULH/SMULH through portable unsigned 32x32 partial products, retained middle carry and modular signed correction. All ignored Ra values preserve the original words and never supply an accumulator. Independent big-integer results, full-product leaves and actual PAC/PLT prefixes with saved X19 destinations pass on MSVC/GCC. Static discovery reaches 135,390 PAC-enabled regions and 40,186 accepted ordinary leaves, while policy-6/7 acceptance remains 1,688/1,710. The global eligible bridge catalog reaches 433; profile permissions and ABIs are unchanged.

The combined [integer-frontier milestone](integer-frontier.md) implements EXTR/immediate ROR and all eight CRC32 variants through the existing value policies. Independent concatenation/polynomial checks and mixed PAC/PLT prefixes pass on both compilers. A single [milestone runner](development-workflow.md) now configures/builds, runs MSVC/GCC checks in parallel, performs fresh surveys/audit, verifies provenance and emits stage logs and summaries. The full pass contains 333 Python tests and 283,401 comparisons per compiler. Static discovery reaches 135,571 PAC-enabled regions and 40,188 ordinary leaves; policy-6/7 acceptance remains 1,688/1,710. The global eligible bridge catalog reaches 434 and the measured integer first-stop frontier falls from 46 to zero.

Development now proceeds in complete capability milestones, including their dependent implementation, integration, evidence, documentation and reviewed dev update. The memory milestones below deliver explicit store effects and measure remaining callee blockers. Wider calls, further layouts, broader loop shapes and remaining ordered/atomic semantics still need work. Complete process startup needs the actual guest ABI, SDK TLS, module initialization, scheduling and service dispatch. SIMD/FP, atomics/exclusives, nonlocal returns and wider indirect-target discovery remain separate requirements. The explicitly authorized startup-prefix experiment has its own bounded execution contract; earlier static surveys and leaf/stack validations keep their no-game-execution scope.

The [memory-callee milestone](memory-callees.md) adds bound memory-leaf policy 2 and stack policy 9/schema 10. It reuses exact operand snapshots/staged stores with image grants, excludes all caller/ancestor stack access in memory leaves, and preserves existing leaf/stack ABIs and permissions. Real direct and exact-PLT callee proofs produce 1,030 additional static framed-root closures, using 360 memory leaves and 1,463 unique call edges. Native synthetic and actual factory prefixes pass on both compilers; these structural game measurements still require runtime memory/GOT conditions and do not establish startup or gameplay readiness.

The [bounded-memory milestone](bounded-memory.md) adds separate leaf policy 3 and stack policy 10/schema 11 for scalar/pair writeback and one linear W/X counter loop. Full original-word/CFG binding, first-header positive/divisible admission of at most 1,024 iterations, independent decrement/latch/guard state checks and a yield-persistent retirement cap constrain execution. Per-step ranks describe the cut DAG; caller bounds include bounded leaf work and all four PLT instructions. Image grants still exclude every caller/ancestor stack byte and schema-11 writes exclude registered GOT slots. Earlier constructors and permissions remain unchanged. The fresh original-byte survey preserves 16,805 preceding memory candidates and adds 554 regions, with 10 new framed-root closures using 12 new leaves and 20 unique call edges. Five used leaves contain loops reached by two upgraded roots; seven are acyclic writeback helpers. The full MSVC/GCC, survey, audit and comparison run passes with an unchanged source fingerprint; private evidence is under `build/milestones/bounded-memory-v1/`. Surveys remain static and supply no callbacks or runtime capabilities.

The separate [RAW startup-prefix contract](startup-bootstrap.md) selects original loader instructions, copies exact words/control/span metadata and checks each native step before publication. Direct and indirect transfers require a registered original target before LR/state changes. Memory effects use captured reads and staged whole-transfer stores; PAC, checkpoint, stack, text and global retirement checks survive yields. This does not broaden leaf/stack policies or prove original function identity.

Startup packages contain fresh unrelocated 4 KiB pages, with writable data/BSS combined and verified zero padding. A separately linked copy audits imports/initializer metadata and supplies relative-pointer probes. The original loader performs relocation; an image-level pristine-byte/metadata claim prevents replay. The experimental context supplies a verified-NPDM-sized guarded stack, zeroed private TLS, an initially unmapped reserved heap and checked QueryMemory/heap/debug/counter services. MSVC and GCC both execute 40,397,142 original instructions through the loader into SDK initialization, then stop before GetInfo ID 11 (handle zero, sub-ID two). Their complete ordered trace digests agree and all eight entry-module relative-pointer probes match independently linked values. Initial X0/X1, logical handles, page/TLS/clock choices remain an explicit process model rather than a proven Switch 2 ABI. The full `build/milestones/startup-bootstrap-v1/` run passes 379 Python tests, seven CTest groups, native comparisons, fresh audits and the source-fingerprint gate. Initialization and gameplay remain incomplete.

The separate [SDK runtime foundation](sdk-runtime.md) adds explicit process metadata/entropy, thread queries, TLS register operations and serialized scalar CAS32/64. It requires an original-byte profile before populating the observed main-thread lock identity and preserves original SDK writes of thread objects. Original-word selection, real PLT stubs, fresh raw relocation, one-shot ownership and full trace hashing continue to apply. Its ordered stage/nnMain goal separates an initialization handoff from diagnostic stops. Service-manager IPC, session ownership and application heap requirements remain concrete initialization dependencies; no successful connection or service response is manufactured.

## Repository boundaries

The separate [checked-memory contract](checked-memory.md) extends the PAC/LR-pair/PLT stack dispatcher through policy 8/schema 9. It binds original effect words, separates read/write grants, checks complete staged store effects, and preserves retained image/key ownership and all frame checkpoints. Earlier constructors keep their permissions. Synthetic mixed callees/full-depth graphs and actual schema-9 factories run on MSVC/GCC; fresh memory surveys and callee frontiers stay static and confer no runtime capabilities.

Only project source and documentation belong in Git. Local configuration, user inputs, extracted content, translated game code, compiled output, and runtime caches belong in ignored directories.
