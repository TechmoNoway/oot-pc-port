# Default display VSync SystemEvent

The separate `--events` opt-in requires `--objects`. It keeps the existing
program/context constructors and enables the trusted declaration's VSync bit;
ordinary object profiles retain a zero bit and their historical guard. The new
source audit supports only the exact SDK build already reviewed for objects.

`tools/system_event_audit.py` binds the whole public GetDisplayVsyncEvent body,
default Display identity, duplicate/cache/clear-mode arguments, the original VI2
default callback constructor, callback slots and canonical private callback
extents. The default duplicate supplies managed readable ownership and forwards
the source clear mode through AttachReadableHandleToSystemEvent and the complete
InterProcessEvent attachment stores. This is a host reimplementation of the
default provider; it does not execute the skipped original VI2 callback table or
create a Nintendo graphics session.

The fresh original symbol census contains 256 aliases at 254 entries, including
the `nnos*` C wrappers missed by the earlier research subset. Seventeen original
functions retain early creation and wait/try/clear/destroy paths. Unsupported
producers/consumers remain guarded, including a call-derived private generic
kernel creator with canonical unwind provenance. The registry has 3051 entries,
within the unchanged 4096 limit. The original CreateSystemEvent in-process branch
must remain: it executes twice before initialization finishes. Guarding the
entire named family would break the existing prefix.

Publication requires a known open Display, a writable nonaliasing aligned output
and its uninitialized tag. It owns a real DXGI VBlank producer and actual
synchronization-only Windows duplicates. The sparse original record contains
self links, auto-clear/initialized/ownership bytes, a registered read token,
zero write token and inter-process tag. Unwritten gaps remain unchanged. No host
handle or pointer is cast into guest data. Tokens do not repeat during an owner
lifetime. A repeated publication returns the source-proved duplicate result.

Original consumers run as guest instructions. Four source-observed syscall
sequences use the scoped token owner: single infinite WaitSynchronization,
ResetSignal, ClearEvent and CloseHandle. Reset misses return the observed result;
failure wakes have priority over data. Unknown handles, other counts/modes and
finite waits remain unsupported. The retained caller bodies, PLTs, exact syscall
register roles and byte sequences are bound to original source. A syscall byte
sequence is not mislabeled as an exported function or canonical FDE extent.

Synthetic native fixtures test record/tag/ownership faults, read rights, worker
failure and cleanup. The generated dispatcher test adds actual SVC execution and
quota yields around publication, wait, reset, reset miss, clear and close, with
vector state and original native-window identity preserved on MSVC/GCC. This
does not claim the game has yet waited on VSync.
