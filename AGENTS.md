# Project instructions

This is an independent native Windows x86-64 port project. The current code provides a host scaffold, verified input preparation, offline linking, ARM64 analysis, checked guest memory, paired/scalar integer C lifting, and native data-only image mapping; do not describe it as a working game port.

- Keep code, documentation, and commit messages in English.
- Keep changes focused and verify behavior before reporting success.
- Keep game files, keys, extracted content, generated game code, and compiled output out of Git.
- Put build output under `build/` and generated game output under `generated/`.
- Implement project code independently. Any future imported third-party code must retain its applicable license and notices.
- Run the native host self-test when changing host code.
- Run `python -B -m unittest discover -s tests -v` when changing input inspection. Test fixtures must be synthetic.
- Build the local ZBIC helper before running segment integration tests. Keep its external dependency under ignored `toolchain/`, with its license intact.
- Linking works on private images and must not execute guest code or invent addresses for unresolved strong symbols. Keep linked images and reports under ignored `build/`.
- Install `tools/requirements-analysis.txt` in the project environment for ARM64 integration tests. Decoder success is not semantic lifter support, and unvisited text must not be called proven data.
- Install `tools/requirements-lifter.txt` for native differential validation. Compile generated synthetic C and compare with the independent reference after semantic changes. Keep generated tests, libraries, and reports under `build/`; do not execute game code in these tests.
- Run the CTest guest-memory self-test after memory changes. Preserve the explicit fault/retirement contract; preflight failures must not mutate a scalar or paired access or perform writeback. Document the distinction from hardware partial-store behavior.
- Runtime packages require a complete verified offline link. Map exact segment/BSS ranges and guarded synthetic stacks; preserve BSS relocations. Validate checksums, bounds, and permissions in the native loader. Do not execute game constructors or infer a usable process startup ABI from successful mapping.
- Leaf verification proves only the declared region's conservative control-flow/register policy. Keep its entry/LR/NZCV preconditions explicit, distinguish metadata candidates from original function identity, and use synthetic whole-function tests with independent expected results. Do not execute game candidates as part of validation.
- Leaf dispatch registers trusted compiled symbols and generated CFG metadata, never guest addresses cast to code pointers or serialized native pointers. Enforce exact entry/return, checkpoint ownership, protected-register and per-instruction edge/count checks. Run the native dispatcher self-test and generated synthetic caller/callee comparisons after dispatcher changes. Do not expand the leaf policy implicitly or register game callbacks in validation.
- Bound registries pin the initial snapshot body hash and current exact read-only text hashes, retain their image, and permit writable runtime data to evolve. Keep native module/image ownership explicit. The separate linear FP/LR caller profile stages its 16-byte frame on a private memory window before commit and protects saved bytes across yields. Validate full synthetic frame/callee execution and negative hash/stack/contract cases on native compilers; do not broaden this profile or execute game selections implicitly.
- The separate local-stack DAG profile uses fixed aligned frames, declared local access spans, acyclic direct calls, and explicit bounded activations. Preserve all current/ancestor frame checkpoints and validate callee stack/code before committing BL. Keep the original leaf/single-caller policies intact. Validate full synthetic call graphs, per-instruction prefixes, maximum depth/stack boundaries, staged-store failures, and generated schema-2 factories with MSVC and GCC. Game callbacks remain unregistered and unexecuted.
- CFG stack policy v2 is explicit opt-in through schema 3 and its separate constructor. Verify closed acyclic body edges, contiguous distinct X19-X28 save slots and reverse restores, exact phase masks, and weighted CFG/call bounds. Protect saved slots from ordinary local accesses; require original register values at saves/restores. Preserve policy-v1 behavior and descriptor layouts. Validate conditional paths, all saved registers, individual prefixes, malformed metadata, staged failures, and actual schema-3 factories on MSVC/GCC; do not execute game selections.
- Fixed-layout policy v3 is explicit through schema 4 and its separate constructor. Normalize SP/FP local offsets, keep FP/LR and sparse save slots disjoint, and validate exact post-instruction SP/FP/LR/ownership states. Claim the full frame after allocation and release only after deallocation, including across yields after record restore. Preserve earlier policies/layouts. Compare synthetic mixed layouts, individual prefixes, full-depth/full-stack cases, failure isolation, and actual schema-4 factories on MSVC/GCC. Generated game selections remain unexecuted.
- Profile surveys must use unchanged source bytes and real production verifier/callee proofs. Never strip PAC/BTI, fabricate callees, or relax policies for acceptance counts. Separate metadata/window discovery blockers, first-failure diagnostics, and accepted candidate regions; prefix observations are diagnostic only. Keep full private reports under build/ and publish aggregate results only. Surveying does not prove original function identity, whole-game coverage, or runtime readiness and must not generate or execute game callbacks.
- PAC is explicit opt-in through its separate context/callback ABI. Preserve the QARMA5/VA39/TBI0 basic model, canonical signing precondition, real signed bits, poisoned-pointer retirement, and unchanged LR on authenticated returns. Never silently strip PAC, treat it as NOP, or broaden old profiles. Keep keys private/immutable across yields; no live-key logging or serialization. Semantic changes require native MSVC/GCC comparisons with the pinned reference configured and checked for enabled QARMA5. No game callbacks may be executed during validation.
- PAC stack policy v4/schema 5 retains its image and reference-counted immutable key context. Preserve exact entry signing, signed record saves/restores, matching AUT/RET keys, approved canonical returns, all ancestor frame checkpoints, and staged fault isolation. Callback types must stay separate; old callback slots are NULL for PAC descriptors. Validate original bytes without stripping/rewriting PAC, including actual schema-5 factories, full-depth boundaries, corrupted metadata/callbacks/keys/frames, and MSVC/GCC reference comparisons. The PAC survey is separate opt-in; default profile results must remain stable and game candidates stay ungenerated/unexecuted.
- No-offset LDAPR/B/H uses the serialized Normal-memory RCpc subset, with natural alignment and 16-byte SP-base preconditions. All scalar/pair/ordered backend transfers must share the same lock per linked instance; do not replace acquire with an unsynchronized byte read or fabricate C atomic pointers over byte backing. Concurrent participants need separate state/fault views, immutable tables/lifetimes, and all shared-byte accesses through the same backend instance. Runtime-image/dispatcher/PAC APIs remain single-threaded. Preserve ABI 2 and old profile memory permissions; validate aligned values/faults with the pinned reference, rejected-domain behavior separately, and real native publication/alias/atomicity stress on MSVC/GCC. Do not claim exhaustive weak-memory equivalence or guest threading readiness.
- Checked-read policy v5/schema 6 is a separate opt-in constructor/descriptor. Bind exact read words to original text, copy explicit ranges within readable retained-image regions, and exclude saved slots, ancestor frames, and all other stack bytes. Capture each complete operand once through the real scalar/pair/acquire backend; give callbacks only a read-only operand snapshot and check their full expected state and window metadata before commit. Preserve old policies, staged local stores, PAC/image ownership, and fault retirement. Validate dynamic pointers, address forms, nesting/depth, range boundaries, malformed callbacks/metadata, evolving data, copied lifetimes, and actual schema-6 factories with MSVC/GCC and the enabled pinned reference. Static read surveys prove structure with runtime obligations, grant no ranges, and must not generate/register/execute game callbacks.
- LR-pair policy v6/schema 7 is explicit opt-in and may mix new LR/X19-X28 pair frames with existing FP layouts and verified register-only leaves. Preserve FP exactly in LR-pair activations, bind matching pre-index/post-index pair words to original text, protect implicit/explicit save slots, and restore the original partner and signed LR before releasing ownership. Active leaf SP/FP/LR checks must use the actual suspended checkpoint. Keep old constructors/policies, read capabilities, PAC ownership, and transactional stores unchanged. Validate all partner registers/orders/keys/return styles, mixed/full-depth calls, individual prefixes, metadata/text/state faults, opening-store retries, ancestor checkpoints, retained lifetimes, and actual schema-7 factories on MSVC/GCC with the enabled pinned reference. Static surveys use real closures and must report unchanged acceptance honestly; no game callbacks may be generated or executed.
- Callee audits must reproduce the real policy-6 discovery/proofs and distinguish unique targets, caller-region/target edges, and overlapping transitive root references. Unseeded target probes use unchanged bounded bytes, remain diagnostic, and never enter production maps or satisfy one another. Preserve metadata failure windows. PLT/GOT annotations require the exact existing relocation-backed pattern and describe a linked snapshot only, never an approved runtime target set, call bypass, or service ABI. Match baseline source/text hashes, limits/model/decoder, and per-module/global aggregate outcomes when requested. Keep detailed addresses/reports private under build, publish aggregate evidence only, and use synthetic tests; do not generate/register/execute game callbacks.
- PLT policy v7/schema 8 is explicit opt-in through its separate constructor and exact relocation-backed ADRP/LDR/ADD/BR descriptors targeting registered ordinary leaves only. Preserve all four instructions, X16/X17 effects, caller LR/SP/FP/PAC state, weighted budgets and frame ownership; never collapse the stub into a direct call or cast guest PCs to native pointers. Bind original stub/leaf hashes and exact words, copy descriptors, retain image/keys, and require the current eight-byte GOT binding to remain the single approved target throughout bridge/leaf yields. Callbacks get empty windows or the exact read-only operand snapshot. Preserve old policies and distinguish retriable preflight failures from latched callback faults. Exclude nonlocal returns/general indirect calls and require synthetic MSVC/GCC reference prefixes, mixed/full-depth cases, changed GOT/code/permissions, malformed effects/metadata, retained lifetimes and actual schema-8 factories. Static surveys use real bridge/leaf/closure proofs, grant no live GOT guarantees or ranges, and never generate/register/execute game callbacks.
- CCMP/CCMN are flag-only value forms with exact fixed-bit checks, separate fallback NZCV, incoming-condition evaluation, ZR sources and W/X arithmetic without carry input. Preserve every GPR/SP and existing profile permissions/ABIs. Semantic changes require independent flag mathematics, pinned-reference MSVC/GCC comparisons, all condition/fallback/input-flag combinations, operand boundaries, complete leaf results and actual PAC/PLT factory prefixes. New instruction support may change discovery/acceptance counts; rerun static surveys on matching source/text hashes and report remaining failures without executing game callbacks.
